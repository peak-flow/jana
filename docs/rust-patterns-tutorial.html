💡 Key Insight

In Laravel, the server renders HTML. In Tauri, the Rust backend only returns data (JSON), and Vue handles all rendering on the client side. Think of it as building a Laravel API + Vue SPA, but packaged as a desktop app.

Common Rust Patterns

Essential patterns you'll use when building Rust applications

📦

Structs (Like PHP Classes)

Structs define data shapes. Unlike PHP classes, they don't have inheritance - use composition instead.

// Define a struct (like a PHP class with only properties)
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Note {
    pub id: String,
    pub title: Option<String>,  // nullable
    pub content: Option<String>,
    pub created_at: i64,
}

// Add methods with impl block
impl Note {
    pub fn is_empty(&self) -> bool {
        self.content.is_none()
    }
}
❓

Option<T> (Nullable Values)

Rust has no null. Option<T> explicitly represents "might have a value".

// PHP: $title = $note->title ?? 'Untitled';

// Rust: Pattern matching
let display_title = match ¬e.title {
    Some(t) => t.clone(),
    None => "Untitled".to_string(),
};

// Shorthand with unwrap_or
let title = note.title.unwrap_or("Untitled".to_string());

// Safe chaining (like PHP's ?->)
let len = note.title.as_ref().map(|t| t.len());
⚡

Result<T, E> (Error Handling)

No exceptions! Functions return Result to indicate success or failure.

// PHP: try { ... } catch (Exception $e) { ... }

// Rust: Result type
fn get_note(id: String) -> Result<Note, String> {
    // ? operator: return early if error
    let note = db_query(&id).await
        .map_err(|e| e.to_string())?;

    Ok(note)  // Explicit success
}

// Caller handles both cases
match get_note(id).await {
    Ok(note) => /* use note */,
    Err(e) => /* handle error */,
}
🔧

Derive Macros (Auto-Implementation)

Automatically implement common traits (like PHP interfaces) for your types.

#[derive(
    Debug,       // println!("{:?}", note)
    Clone,       // note.clone()
    Serialize,   // Convert to JSON
    Deserialize, // Parse from JSON
    PartialEq,   // note1 == note2
)]
pub struct Note {
    // fields...
}

// Now you can:
let json = serde_json::to_string(¬e)?;
let copy = note.clone();
println!("{:?}", note);
🔐

Ownership & Borrowing

Rust's killer feature - memory safety without garbage collection.

// MOVE: ownership transfers
let s1 = String::from("hello");
let s2 = s1;  // s1 is now invalid!

// BORROW: temporary access with &
fn print_note(note: &Note) {  // borrows, doesn't own
    println!("{}", note.id);
}  // note still valid after call

// MUTABLE BORROW: exclusive write access
fn update_note(note: &mut Note) {
    note.title = Some("New Title".to_string());
}

// CLONE: explicit copy when needed
let copy = note.clone();
🎯

Pattern Matching

Powerful switch-like syntax that ensures all cases are handled.

// PHP: switch($status) { case 'draft': ... }

// Rust: exhaustive matching
enum Status { Draft, Published, Archived }

let message = match status {
    Status::Draft => "Not yet published",
    Status::Published => "Live!",
    Status::Archived => "No longer available",
};  // Must handle ALL variants!

// Destructuring in match
match result {
    Ok(note) => println!("Got: {}", note.id),
    Err(e) => eprintln!("Error: {}", e),
}

// if let for single pattern
if let Some(title) = note.title {
    println!("Title: {}", title);
}

Error Handling Patterns

How to handle errors gracefully in Rust vs PHP

// Laravel: Exceptions bubble up
class NoteController
{
    public function show($id)
    {
        try {
            $note = Note::findOrFail($id);
            return view('notes.show', compact('note'));
        } catch (ModelNotFoundException $e) {
            return response()->json(['error' => 'Not found'], 404);
        } catch (\Exception $e) {
            report($e);
            return response()->json(['error' => 'Server error'], 500);
        }
    }
}
// Rust: Explicit error handling with Result

// Define custom error type (optional but recommended)
#[derive(Debug)]
enum AppError {
    NotFound(String),
    Database(String),
    Validation(String),
}

fn get_note(id: &str) -> Result<Note, AppError> {
    // Early return on error with ?
    let note = db_find(id)
        .map_err(|e| AppError::Database(e.to_string()))?;

    match note {
        Some(n) => Ok(n),
        None => Err(AppError::NotFound(format!("Note {} not found", id))),
    }
}

// Using the function
let result = get_note("abc123");
match result {
    Ok(note) => println!("Found: {:?}", note),
    Err(AppError::NotFound(msg)) => println!("404: {}", msg),
    Err(AppError::Database(msg)) => println!("DB Error: {}", msg),
    Err(_) => println!("Unknown error"),
}
// Tauri Commands: Return Result<T, String>

#[tauri::command]
pub async fn get_note(
    id: String,
    state: State<'_, DbState>
) -> Result<Note, String> {
    // map_err converts any error to String for frontend
    let note = sqlx::query_as::<_, Note>(
        "SELECT * FROM notes WHERE id = ?"
    )
    .bind(&id)
    .fetch_optional(&state.pool)
    .await
    .map_err(|e| format!("Database error: {}", e))?;

    note.ok_or_else(|| format!("Note not found: {}", id))
}

// Frontend catches errors:
// try {
//   const note = await invoke("get_note", { id });
// } catch (error) {
//   console.error(error); // "Note not found: abc123"
// }
⚠️ Common Mistake

Don't use .unwrap() or .expect() in production code - they panic (crash) on error. Always use ? or match to handle errors properly. Reserve .unwrap() for tests and prototyping only.

State Management

Managing shared state between components

Laravel vs Tauri State

🔴

Laravel (Service Container)

// Service Provider
public function register()
{
    $this->app->singleton(
        NoteService::class,
        fn() => new NoteService(config('notes'))
    );
}

// Controller - injected automatically
public function __construct(
    private NoteService $notes

🦀

Tauri (Managed State)

// Define state wrapper
pub struct DbState {
    pub pool: SqlitePool,
}

// Register in main.rs
tauri::Builder::default()
    .manage(DbState { pool })  // Add state
    .invoke_handler(...)
    .run(...);

// Access in commands
#[tauri::command]
pub async fn get_note(
    state: State<'_, DbState>  // Injected!
) -> Result<Note, String> {
    // Use state.pool
}

Frontend State (Vue 3)

// Composable pattern - like Laravel Service classes but reactive
// src/composables/useNotes.ts

import { ref, readonly } from 'vue';
import { invoke } from '@tauri-apps/api/core';

// Private state
const notes = ref<Note[]>([]);
const loading = ref(false);

// Export readonly to prevent external mutation
export function useNotes() {
    async function fetchNotes() {
        loading.value = true;
        notes.value = await invoke<Note[]>('list_notes');
        loading.value = false;
    }

    return {
        notes: readonly(notes),
        loading: readonly(loading),
        fetchNotes,
    };
}

Async Patterns

How async/await works in Rust vs PHP

Concept PHP/Laravel Rust
Default behavior Synchronous (blocking) Async by choice (non-blocking)
Async syntax Queues, Promises (JS) async fn + .await
Runtime PHP-FPM process per request Tokio (multi-threaded executor)
Parallelism Multiple processes Tasks on thread pool
Background jobs Queue workers (Redis, DB) tokio::spawn() 
// Running multiple async operations concurrently

use tokio::join!;

async fn load_dashboard() -> Result<Dashboard, Error> {
    // Sequential (like PHP) - slow
    let notes = get_notes().await?;
    let settings = get_settings().await?;
    let stats = get_stats().await?;

    // Concurrent (all at once) - fast!
    let (notes, settings, stats) = join!(
        get_notes(),
        get_settings(),
        get_stats()
    );

    Ok(Dashboard {
        notes: notes?,
        settings: settings?,
        stats: stats?,
    })
}

// Background task (like Laravel queue dispatch)
tokio::spawn(async move {
    send_email(user_id).await;
});  // Returns immediately, runs in background
// Tokio is the async runtime (like PHP-FPM but for async)

// In main.rs - Tauri handles this for you
#[tokio::main]  // Sets up the runtime
async fn main() {
    tauri::Builder::default()
        .run(...)
        .expect("error running app");
}

// Key Tokio features:

// 1. Sleep (non-blocking delay)
tokio::time::sleep(Duration::from_secs(5)).await;

// 2. Timeout (like PHP max_execution_time)
let result = tokio::time::timeout(
    Duration::from_secs(30),
    long_operation()
).await;

// 3. Select (race multiple futures)
tokio::select! {
    result = operation_a() => /* a finished first */,
    result = operation_b() => /* b finished first */,
}

Rust Module System

How to organize code in Rust (like Laravel's app/ folder)

Jana Project Structure

  • src-tauri/
    • src/
      • main.rs - Entry point, registers commands
      • db.rs - Database setup & migrations
      • commands/
        • mod.rs - Module declaration
        • notes.rs - Note CRUD commands
        • llm.rs - AI summarization
        • settings.rs - Settings commands
    • Cargo.toml - Dependencies (like composer.json)
    • tauri.conf.json - App configuration
  • src/ (Frontend)
    • App.vue
    • components/
    • composables/

Module Declaration

// src-tauri/src/main.rs
mod db;        // Loads db.rs
mod commands;  // Loads commands/mod.rs

// src-tauri/src/commands/mod.rs
pub mod notes;     // Loads commands/notes.rs
pub mod llm;       // Loads commands/llm.rs
pub mod settings;  // Loads commands/settings.rs

// Using in main.rs
use crate::commands::notes::create_note;
use crate::db::{init, DbState};

Visibility (pub)

// Private by default (unlike PHP which is public)
struct PrivateStruct;  // Only visible in this file

// Public - visible everywhere
pub struct PublicStruct;

// Pub(crate) - visible within this crate only
pub(crate) struct InternalStruct;

// Pub fields
pub struct Note {
    pub id: String,         // Accessible from outside
    pub(crate) secret: i32,  // Internal only
    internal: bool,          // Private to this module
}
